Reading code you didn't write

She designs the product. Today she opened the repo.

A designer at a four-person startup. The agent has been shipping for a week and she wants to understand what's underneath it — not to change it, just to stop nodding at words she doesn't know.

YOU

What is this file even doing?

◎
read_file

It's the door everything comes through. Every request hits this file first, and it checks one thing — are you who you say you are — before letting anything past. The three functions below are just three ways of asking that: a password, a token, a link from an email.

YOU

What's interface mean, at the top there?

◎

A shape, not a thing. It says "anything calling itself a User must have these five fields" — so if the agent ever builds one missing an email, the compiler catches it before you ever run it. It's a promise the code makes to itself.

Git, finally

He's been copying commands off a sticky note for two years.

A self-taught developer who ships fine until git goes sideways. He knows the four commands that usually work and has no picture of what any of them do.

YOU

It says my branch and origin have diverged. I don't know what that means and I'm scared to type anything.

◎
git_summary

You both wrote. You made two commits here; someone pushed one to the server. Neither is wrong — they're just two versions of the story that split at the same point. Nothing is lost, and nothing is broken.

YOU

So what do I actually type?

◎

Rebase. It takes your two commits off, replays theirs, then puts yours back on top — so the story reads in one line instead of a fork. git pull --rebase. If it stops and asks you about a file, that's a conflict, and I'll walk you through that one when we get there.

Watching the agent work

What it can do

Four things, done well.

Every one of them is a switch in your panel. Turn one off and it's genuinely off — Spotter isn't told the tool exists.

Watch the screen

Reads your terminal, your editor, an error too small to squint at. Can keep an eye on one window and speak up the moment a build finishes or a test goes red.

Read your project

Opens files, searches the codebase, and reads the git history — so "what changed" is answered from the diff, not from a guess.

Run commands

Your tests, your build, your linter, git. Then the result in a clause — how many passed, and the first one that actually matters. Destructive commands get read back first.

Remember the project

The decisions you made, the conventions you hold, what you were in the middle of. You don't re-explain your project every morning.

Plainly

What it is, and what it isn't.

It doesn't write your code

Your agent does that. Spotter watches, checks, and explains. It can edit and commit when you ask it to — but that's not what it's for.

You hold every switch

Watching, reading, running, typing for you — each is a toggle, and typing is off until you turn it on. A capability that's off isn't offered to the model at all.

Memory stays on your Mac

What it learns about your project is stored in a local database you can open and delete. To index a screenshot it captures, it sends that image to Google's vision model — that part isn't local, and you can switch memory off entirely.
